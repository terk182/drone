2 ทฤษฎีที่ต้องรู้

ก่อนลงมือสร้าง ต้องเข้าใจ 5 เรื่องหลัก: ฟิสิกส์การบิน · คณิตศาสตร์ท่าทาง (มุมออยเลอร์) · เซนเซอร์ · ตัวควบคุม PID · การสื่อสาร

2.1 ฟิสิกส์การบินของควอดคอปเตอร์

✈️ แรงยก (Thrust)

ใบพัดหมุนแล้วดันอากาศลงข้างล่าง เกิดแรงปฏิกิริยาดันตัวโดรนขึ้นข้างบน (กฎข้อที่ 3 ของนิวตัน)

โดรนลอยอยู่นิ่งต้องได้แรงยกเท่ากับน้ำหนัก:

4 × T = m × g

T = แรงยกต่อมอเตอร์, m = มวลโดรน, g = 9.81 m/s² — ถ้าแรงยกมากกว่าน้ำหนัก → โดรนไต่ขึ้น (throttle มากขึ้น)

🔄 แรงบิด (Torque)

มอเตอร์ที่หมุนตามเข็มนาฬิกา (CW) จะทำให้เฟรมปั่นทวนเข็ม (action–reaction) ดังนั้นเราจึงสลับทิศใบพัด CW–CCW–CW–CCW เพื่อตัดแรงบิดหัน (yaw) ให้หักล้างกันเอง

เวลา "หันซ้าย/ขวา" ก็คือการเร่งมอเตอร์คู่ CW หรือ CCW ให้แรงบิดไม่สมดุลกันนั่นเอง

2.1.1 กฎของนิวตัน + ไม้กระดก — เข้าใจแรง/แรงบิดแบบง่าย

หลายคนงงกับ "แรงบิดหักล้าง" ของโดรน ลองคิดเป็นไม้กระดกก่อน: ไม้กระดกสมดุลเมื่อแรงสองข้างเท่ากัน (ระยะจากจุดหมุนเท่ากัน) — โดรนก็เหมือนกัน แค่ "แรง" เป็นแรงบิดจากใบพัด (มอเตอร์หมุน → เฟรมอยากหมุนสวนกลับ) ถ้าสองข้างเท่ากัน = ลอยนิ่งไม่หันเอง

🧊 กฎข้อ 1 — ความเฉื่อย

ไม่มีแรงลัพธ์ → อยู่นิ่ง/เคลื่อนที่ตรงคงที่
โดรนลอยนิ่ง = แรงลัพธ์เป็นศูนย์ (แรงยกรวม = น้ำหนัก และแรงบิด CW = CCW)

🏃 กฎข้อ 2 — F = ma

แรงลัพธ์ ≠ 0 → เกิดความเร่ง
เร่งมอเตอร์ข้างหนึ่ง → แรงไม่สมดุล → โดรนเอียง/เร่งไปทางนั้น (เหมือนไม้กระดกหนักข้าง → เอียงข้างนั้น)

🤝 กฎข้อ 3 — กิริยา/ปฏิกิริยา

ทุกแรงมีคู่เท่ากันทิศตรงข้าม
ใบพัดดันอากาศลง → อากาศดันโดรนขึ้น (แรงยก) · มอเตอร์หมุน CW → เฟรมอยากหมุนทวนเข็ม (แรงบิดโต้กลับ)

⚖️ ไม้กระดกจำลอง — เลื่อนแถบดู "สมดุลแรงบิด" (Yaw)

ซ้าย = แรงบิดคู่ CW (M1,M3) · ขวา = คู่ CCW (M2,M4) — แรงบิด τ = แรง F × ระยะ d (ระยะสองข้างเท่ากัน) → สมดุลเมื่อ F ซ้าย = F ขวา

ทิศทางการหมุนและการควบคุม Roll / Pitch / Yaw

🔼 Throttle (คันเร่ง)

เพิ่ม/ลดกำลังมอเตอร์ทั้ง 4 ตัวพร้อมกัน → โดรนขึ้น/ลง

↔️ Roll (เอียงซ้าย-ขวา)

คู่ทแยง M1,M2 กับ M3,M4 ต่างกัน (ข้างหนึ่งเร่ง อีกข้างผ่อน) → โดรนเอียงไปด้านข้าง

↕️ Pitch (ก้ม-เงย)

คู่หน้า M1,M4 กับคู่หลัง M2,M3 ต่างกัน → โดรนโน้มหน้า/หลัง

🔄 Yaw (หันซ้าย-ขวา)

คู่ CW กับคู่ CCW ต่างกัน → เกิดแรงบิดหันตัว

สมการ Mixer (จับคู่คำสั่ง → กำลังมอเตอร์แต่ละตัว)

quad mixer# โดยประมาณ X-quad (ค่าจริงดูใน power_distribution_stock.c)
m1 = throttle − roll/2  + pitch/2 + yaw
m2 = throttle − roll/2  − pitch/2 − yaw
m3 = throttle + roll/2  − pitch/2 + yaw
m4 = throttle + roll/2  + pitch/2 − yaw

🧮 ตัวอย่างการคำนวณ Mixer

สมมติสั่ง throttle=50 (สเกล 0–100) แล้วเพิ่มคำสั่งทีละแกน — สังเกตว่า ผลรวมกำลังทั้ง 4 ตัว = 200 เท่าเดิมเสมอ (แรงยกสุทธิคงที่ แค่ย้ายแรงไปฝั่งที่ต้องการ):

↕️ Pitch: ก้มไปข้างหน้า

throttle=50, pitch=10

m1 = 50 + 10/2 = 55   (หน้า-ซ้าย)
m2 = 50 − 10/2 = 45   (หลัง-ขวา)
m3 = 50 − 10/2 = 45   (หลัง-ซ้าย)
m4 = 50 + 10/2 = 55   (หน้า-ขวา)

คู่หน้า M1,M4 = 55 > คู่หลัง M2,M3 = 45 → โดรนโน้มไปข้างหน้า

↔️ Roll: เอียงด้านข้าง

throttle=50, roll=10

m1 = 50 − 10/2 = 45   (หน้า-ซ้าย)
m2 = 50 − 10/2 = 45   (หลัง-ขวา)
m3 = 50 + 10/2 = 55   (หลัง-ซ้าย)
m4 = 50 + 10/2 = 55   (หน้า-ขวา)

คู่ทแยง M3,M4 = 55 > คู่ทแยง M1,M2 = 45 → เอียงไปด้านข้าง

🔄 Yaw: หันซ้าย

throttle=50, yaw=10

m1 = 50 + 10 = 60   (CW)
m2 = 50 − 10 = 40   (CCW)
m3 = 50 + 10 = 60   (CW)
m4 = 50 − 10 = 40   (CCW)

คู่ CW M1,M3 = 60 > คู่ CCW M2,M4 = 40 → หมุนซ้าย (ทวนเข็มนาฬิกา)

🛸 โดรน 3 มิติ — ลากหมุนมุมมอง / สกรอลล์ซูม · ความเอียง ใบพัด และลูกศรแรงขับ เปลี่ยนตาม slider ด้านบน
กำลังโหลดโมเดล 3D…

ใบพัด เขียว = CW · น้ำเงิน = CCW — ความเร็วใบพัดและลูกศรสีทอง = กำลัง m1–m4 ที่คำนวณได้จาก slider

การหักล้างแรงบิดของใบพัด (Torque cancellation)

ใบพัดหมุนดันอากาศลงเพื่อสร้างแรงยก แต่ การหมุนนั้นสร้างแรงบิดโต้กลับ (reaction torque) ในทิศตรงข้ามเสมอ — ใบพัด CW จะผลักเฟรมให้อยากหมุนทวนเข็ม ถ้าใบพัดทั้ง 4 หมุนทิศเดียวกัน โดรนจะปั่นหมุนรอบแกนตั้งเอง (yaw spin) ควบคุมไม่ได้

⚖️ วิธีหักล้าง

หมุนสลับทิศ 2+2: M1+M3 (ซ้าย) หมุน CW, M2+M4 (ขวา) หมุน CCW — เมื่อ throttle เท่ากัน แรงบิด CW กับ CCW หักล้างกันพอดี → โดรนลอยนิ่งไม่หันเอง

🔄 ใช้หันซ้าย/ขวา (Yaw)

ทำให้ไม่สมดุลชั่วคราว: เพิ่มคู่ CW (M1,M3) → หมุนซ้าย · เพิ่มคู่ CCW (M2,M4) → หมุนขวา — โดยแรงยกสุทธิยังเท่าเดิม

ต้องการทำผล
หันซ้ายเพิ่มคู่ CW (M1,M3) / ลดคู่ CCW (M2,M4)แรงบิด CW ชนะ → หมุนทวนเข็ม (ซ้าย)
หันขวาเพิ่มคู่ CCW (M2,M4) / ลดคู่ CW (M1,M3)แรงบิด CCW ชนะ → หมุนตามเข็ม (ขวา)

ดูจากสมการ mixer ด้านบน: เทอม yaw มีเครื่องหมายตรงข้ามกันระหว่างคู่ CW (m1, m3 = +yaw) กับคู่ CCW (m2, m4 = −yaw) — นี่คือการสั่ง "หักล้าง" ในโค้ด

⚠️ ตอนประกอบ ใบพัด CW กับ CCW ต่างกัน (มุมเอียงคนละทิศ) — ใส่ผิดทิศจะได้แรงยกผิดทาง บินไม่ขึ้น และเกลียวล็อกใบพัดก็คนละทิศ (self-tightening) หมุนตามแรงบิดแล้วแน่นเอง

2.2 คณิตศาสตร์ท่าทาง — มุมออยเลอร์ (Euler angles) และ Quaternion

ท่าทางของโดรน (attitude) คือ "ตอนนี้เอียง/หันไปทางไหน" — เขียนแทนด้วยการหมุน 3 แกน: roll (φ) รอบแกนหน้า-หลัง, pitch (θ) รอบแกนซ้าย-ขวา, yaw (ψ) รอบแกนตั้ง เรียกรวมว่า มุมออยเลอร์ (Euler angles) ตามชื่อ เลออนฮาร์ด ออยเลอร์ นักคณิตศาสตร์ชาวสวิสผู้วางรากฐานกลศาสตร์การหมุน

🔄 Roll φ (แกน X)

เอียงซ้าย-ขวา — คู่ทแยง M1,M2 vs M3,M4

↕️ Pitch θ (แกน Y)

ก้ม/เงย — คู่หน้า/หลัง M1,M4 vs M2,M3

🧭 Yaw ψ (แกน Z)

หันซ้าย/ขวา — ควบคุมโดยคู่ CW vs CCW

Rotation matrix — แปลงมุม → ทิศทางใน 3 มิติ

การหมุนรอบแต่ละแกนเขียนเป็นเมทริกซ์ (ให้ C = cos, S = sin):

rotation matrices# Rz(ψ) · Ry(θ) · Rx(φ) — ลำดับ Z-Y-X
Rx(φ) = | 1   0     0   |    Ry(θ) = | cosθ  0  sinθ |    Rz(ψ) = | cosψ −sinψ 0 |
         | 0  cosφ −sinφ |             |  0    1   0  |             | sinψ  cosψ 0 |
         | 0  sinφ  cosφ |             | −sinθ 0  cosθ |             |  0     0    1 |

Rรวม = Rz(ψ) · Ry(θ) · Rx(φ)  →  ทิศทาง3D = Rรวม · เวกเตอร์อ้างอิง

⚠️ ลำดับการหมุนสำคัญมาก การหมุนไม่สลับที่กัน (non-commutative): Rx·Ry ≠ Ry·Rx — เหมือน "เปิดประตูแล้วหมุนตัว" กับ "หมุนตัวแล้วเปิดประตู" ผลไม่เหมือนกัน firmware จึงต้องใช้ลำดับเดียวกันตลอด (ที่นี่ Z-Y-X)

Gimbal lock — จุดอ่อนของมุมออยเลอร์

เมื่อ pitch = ±90° แกน roll กับ yaw จะทับกัน (เสีย 1 องศาอิสระ) → มุมกระโดด/คำนวณเพี้ยน ระบบจริงจึงนิยมใช้ quaternion (w, x, y, z) 4 ตัวเลขแทนการหมุน — ไม่มี gimbal lock, คำนวณเสถียร และเป็นหัวใจของ Madgwick / Mahony filter ใน firmware โดรน (เฟิร์มแวร์ ESP-FLY ใช้วิธีนี้)

สมการการหมุนของออยเลอร์ (Euler's rotation equation) — ฟิสิกส์

กฎข้อ 2 ของนิวตัน สำหรับการหมุน: แรงบิด τ ทำให้เกิดความเร่งเชิงมุม โดยสัมพันธ์กับโมเมนต์ความเฉื่อย I และความเร็วเชิงมุม ω:

τ = I·α + ω × (I·ω)    (α = ω̇ = ความเร่งเชิงมุม)

I·α — เทอม "มวล×ความเร่ง"

แรงบิดที่ทำให้เกิดความเร่งเชิงมุม เปรียบเหมือน F = m·a ในการหมุน — I คือ "ความเฉื่อยต่อการหมุน" (ขึ้นกับมวล + การกระจายตัว เช่น แขนยาว ๆ ยากกว่าจะหมุน)

ω × (I·ω) — เทอมไจโรสโคปิก

ผลจากการหมุนหลายแกนพร้อมกัน ทำให้แรงบิด "ปนกัน" (cross-coupling) เช่น หัน yaw พร้อมก้ม pitch จะเกิดแรงบิด roll แทรก — ระบบควบคุมต้องชดเชย โดรนที่เล็ก/เบาจึงควบคุมง่ายกว่าโดรนใหญ่

เขียนแยกแต่ละแกน (โดยประมาณ เมื่อแกนหลักตรงกับแกนเฉื่อย):

สมการแยกแกนτx = Ixx·ω̇x + (Izz − Iyy)·ωy·ωz
τy = Iyy·ω̇y + (Ixx − Izz)·ωx·ωz
τz = Izz·ω̇z + (Iyy − Ixx)·ωx·ωy

เทอม (Izz−Iyy)·ωy·ωz ฯลฯ คือตัวที่ทำให้ "หมุนแกนเดียวแล้วแกนอื่นขยับตาม" — นี่คือเหตุผลที่ต้องใช้ Rate PID ควบคุมอัตราหมุนแต่ละแกน และเหตุผลที่ firmware รัน control loop เร็ว ๆ (~500 Hz)

จากทฤษฎี → โค้ดจริง

  • firmware ใช้ Mahony/Madgwick หลอมรวม accel + gyro → ได้มุมออยเลอร์ (roll/pitch/yaw) หรือ quaternion
  • มุมที่ได้ถูกส่งเข้า PID ตัวนอก (attitude) แล้วไล่ต่อไป mixer → มอเตอร์ (ดูหัวข้อ 2.4)
  • ใน cflib เราอ่านค่า stabilizer.roll / stabilizer.pitch / stabilizer.yaw ได้ตรง ๆ — ค่าเหล่านี้คือมุมออยเลอร์นั่นเอง

2.3 เซนเซอร์ IMU (Inertial Measurement Unit)

📏 Accelerometer (มาตรความเร่ง)

  • วัดความเร่ง 3 แกน (หน่วย g)
  • ตอนอยู่นิ่งจะรู้ทิศ "ลง" (แรงโน้มถ่วง) → หา roll/pitch ได้แม่น
  • ข้อเสีย: ตอนโดรนเคลื่อนที่/สั่น จะมี noise เยอะ

🌀 Gyroscope (ไจโรสโคป)

  • วัดอัตราการหมุนเชิงมุม (°/s) รอบ 3 แกน
  • ตอบสนองเร็ว ใช้ integrate หาท่าทางได้ทันที
  • ข้อเสีย: มี drift (ค่าลอยสะสม) เมื่อเวลาผ่านไป
💡 Sensor Fusion (การหลอมรวมเซนเซอร์) ใช้จุดเด่นของทั้งคู่: accel คุมระยะยาว (แก้ drift ของ gyro) + gyro คุมช่วงสั้น (ตอบสนองไว) → ได้ท่าทางแม่นยำ เช่น Complementary Filter, Madgwick หรือ Mahony filter

2.4 ตัวควบคุม PID

PID คือสูตรคณิตศาสตร์ที่ใช้ "ผิดพลาดเท่าไหร่ → ต้องชดเชยเท่าไหร่" ให้โดรนกลับไปอยู่ในท่าที่สั่ง:

u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt

P — Proportional

ตอบตาม "ความผิดพลาดตอนนี้" — ยิ่งเอียงมากยิ่งเร่งแรง แค่ P อย่างเดียวจะแกว่ง/เหลื่อม

I — Integral

สะสม "ความผิดพลาดสะสม" — กำจัดค่าเหลื่อมคงค้าง (เช่น โดรนเอียงค้างเล็กน้อยตลอด)

D — Derivative

ดู "แนวโน้มความเร็วของความผิดพลาด" — ช่วยหน่วง ลดการแกว่ง (damping)

Cascade control: ควบคุมเป็น 2 ชั้น

2.5 การสื่อสาร (WiFi + UDP + CRTP)

  • ESP32-S3 เปิด WiFi Access Point ชื่อ ESP-DRONE_XXXXXXXXXXXX รหัส 12345678
  • คอมพิวเตอร์/แอปเชื่อมต่อ WiFi นี้ แล้วส่งคำสั่งเป็นแพ็กเก็ต UDP ไปที่ 192.168.43.42:2390
  • โปรโตคอล CRTP (Crazyflie Radio Transfer Protocol) — โครงสร้างแพ็กเก็ต: header + payload + checksum แบ่งเป็น port/channel เช่น port 0 = setpoint (คำสั่งบิน), port 5 = log (อ่านค่าข้อมูล), port 2 = param
  • ไลบรารี cflib (Python) จัดการโปรโตคอลนี้ให้เรา ใช้ควบคุม/อ่านค่าจากโดรนได้ง่าย

3.3 ขั้นตอนการประกอบ

  1. เตรียมโครงและติดตั้งมอเตอร์ — ยึดมอเตอร์ 4 ตัวเข้ากับแขนโครงแบบ X-quad: M1 หน้า-ซ้าย · M4 หน้า-ขวา · M2 หลัง-ขวา · M3 หลัง-ซ้าย ยังไม่ใส่ใบพัด
  2. ต่อวงจรจ่ายไฟมอเตอร์ — มอเตอร์แต่ละตัวต่อผ่าน MOSFET (Drain→มอเตอร์, Source→GND, Gate→GPIO 4–7) พร้อมไดโอดคร่อมกัน back-EMF
  3. ต่อโมดูล IMU ผ่าน I2C — VCC→3V3, GND→GND, SDA→GPIO8, SCL→GPIO9 (ลองต่อ INT→GPIO13 ด้วย ถ้ามี)
  4. ต่อ LED สถานะ — LED เขียว=GPIO2, น้ำเงิน=GPIO11, แดง=GPIO43 (ผ่าน R 330Ω อนุกรม)
  5. ต่อแบตเตอรี่/แหล่งจ่ายไฟ — ตรวจแรงดันให้ถูกต้อง แล้วต่อเป็นลำดับสุดท้าย
  6. ตรวจเช็คด้วยมัลติมิเตอร์ — วัด 3V3, GND, ตรวจไม่มีลัดวงจร ก่อนเสียบ USB เข้าคอมพิวเตอร์
  7. ใส่ใบพัดให้ถูกทิศ — M1/M3 = CW, M2/M4 = CCW (ดูเครื่องหมายบนใบพัด) — ใส่ตอนจะบินจริงเท่านั้น

  • มอเตอร์แต่ละตัวต่อกับ GPIO ถูกตัว (M1=4, M2=5, M3=6, M4=7)
  • มีแหล่งจ่ายไฟ/แบตเตอรี่พร้อม และรู้แรงดันที่ถูกต้อง

📡 RF / เสาอากาศตอนประกอบ

ปัญหาเจอบ่อยมาก: โดรนอยู่นอก PCB แล้ว WiFi เจอ พอติดลง PCB แล้ว WiFi หาย — สาเหตุหลักไม่ใช่ซอฟต์แวร์ แต่คือ เสาอากาศถูก PCB บัง (antenna detuning)

⚠️ อาการที่บ่งชี้ boot log ขึ้น wifi_init_softap complete (ซอฟต์แวร์ WiFi ทำงาน) แต่สแกนหา SSID ไม่เจอแม้อยู่ใกล้ ๆ · เอาบอร์ดออกจาก PCB แล้วเจอทันที

กฎ 4 ข้อ สำหรับ RF ให้ดี

1️⃣ เสาอากาศพ้นขอบบอร์ด

ย้ายโมดูลให้ส่วนเสาอากาศยื่นเลยขอบ PCB (ดีที่สุด) หรือกันพื้นที่ทองแดงใต้เสาอากาศ ~10×5mm ขึ้นไป

2️⃣ ห้ามสายไฟพาด

สาย USB / สายมอเตอร์ / สายแบตเตอรี่ อย่าให้พาดหรือวนใกล้เสาอากาศ — สายไฟทำตัวเป็นเสาอากาศรบกวน

3️⃣ ไม่มีโลหะบัง

น็อต เสา เฟรมโลหะ ตัวเก็บประจุ ต้องห่างจากเสาอากาศอย่างน้อย ~1 ซม.

4️⃣ แหล่งจ่ายไฟนิ่ง

ไฟเลี้ยง ESP32 ต้องสะอาด (ตัวเก็บประจุกรอง 100µF + 100nF ใกล้ VCC) — ไฟตก/มี noise ทำให้ RF อ่อน

ทดสอบยืนยันใน 1 นาที

  1. ยกโมดูลขึ้นจาก PCB ~1 ซม. (ให้เสาอากาศลอยพ้นบอร์ด)
  2. สแกน WiFi ด้วยโทรศัพท์หรือ netsh wlan show networks
  3. เจอ ESP-DRONE_XXXXXXXXXXXX ทันที = ยืนยันว่าเสาอากาศถูกบัง → จัดตำแหน่งตามกฎข้อ 1–4

4.3.1 Flash ผ่านเบราว์เซอร์ (ESP-Launchpad) — เหมาะสำหรับนักเรียน ⭐

วิธีนี้ ไม่ต้องติดตั้ง ESP-IDF — นักเรียน flash ผ่านเบราว์เซอร์ (WebSerial) ได้เลย เหลือแค่ 3 คลิก และใช้เฟิร์มแวร์ merged.bin ไฟล์เดียว (รวม bootloader + partition table + app แล้ว — flash ที่ address 0x0) ผ่านการทดสอบแล้วว่าบูทได้ Ready to fly. เหมือน flash 3 ไฟล์แยก

🌐 แบบ One-click (แนะนำสำหรับห้องเรียน)

  1. เปิดลิงก์นี้ใน Chrome/Edge:
    espressif.github.io/esp-launchpad/minimal-launchpad/?flashConfigURL=…/config.toml
  2. เสียบสาย USB (สายข้อมูล) เข้าบอร์ด
  3. กด Connect → เลือกพอร์ต USB Serial Device (COMxx)
  4. กด Flash → รอจนจบ (บาร์เต็ม)
  5. ถอด-เสียบ USB ใหม่ (ปลดล็อก IMU) → เสร็จพร้อมบิน!

🛠️ แบบ DIY (สำรอง — ไม่ต้อง host ไฟล์)

  • บอร์ด ESP32-S3 SuperMini เป็น native USB (VID 303A) — ESP-Launchpad รองรับโดยตรง ไม่ต้องกด BOOT
  • สาย USB ต้องเป็นสาย ข้อมูล ไม่ใช่สายชาร์จอย่างเดียว

🎮 บังคับบิน (Virtual joystick)

🕹️ จอยซ้าย

ดันขึ้น-ลง = Throttle (ความสูง) · เลื่อนซ้าย-ขวา = Yaw (หันซ้าย/ขวา)

🕹️ จอยขวา

ดันขึ้น-ลง = Pitch (ก้ม/เงย — ไปหน้า/หลัง) · เลื่อนซ้าย-ขวา = Roll (เอียงซ้าย/ขวา)

  1. ปลดล็อกมอเตอร์ (arm) — ถ้าโดรนไม่ตอบสนอง ให้ลองดัน throttle ลงสุดค้าง 1–2 วินาที (หลายแอปใช้วิธีนี้ก่อนบิน)
  2. ดัน throttle ขึ้นช้า ๆ — โดรนเริ่มยกตัว ค่อย ๆ ปรับจนลอยนิ่ง
  3. บังคับ roll/pitch/yaw เบา ๆ — โดรน DIY ขนาดเล็กไวต่อการสั่ง อย่ากระตุกแรง ๆ
  4. ลงจอด — ลด throttle ช้า ๆ จนแตะพื้น แล้วทำท่าล็อก (disarm)

⚠️ ข้อควรระวังเมื่อใช้โทรศัพท์

  • ระยะ WiFi สั้น (~10–30 ม.) — บินในห้อง/พื้นที่เปิดใกล้ตัว อย่าบินไกลเกินสายตา
  • ถ้า WiFi หลุด โดรนจะหยุดรับคำสั่ง (~500ms) — ต้องค่อย ๆ ลด throttle เสมอ
  • ถอดใบพัดก่อนตอนฝึกซอฟต์แวร์/ทดสอบมอเตอร์ — ใส่ใบพัดเฉพาะตอนพร้อมบินจริง

Python — flight scriptimport sys, time
sys.path.insert(0, r'D:\drone_1\cflib-esplane')
from cflib.crazyflie import Crazyflie

URI = 'udp://192.168.43.42:2390'
cf = Crazyflie()
cf.open_link(URI); time.sleep(2)   # รอเชื่อมต่อ

def setpoint(roll=0, pitch=0, yawrate=0, thrust=0):
    cf.commander.send_setpoint(roll, pitch, yawrate, thrust)
    time.sleep(0.02)               # ส่งทุก ~20ms — ห้ามหยุดเกิน 500ms

setpoint()                              # thrust=0 → ปลดล็อก (arm)
time.sleep(1)

for t in range(0, 40001, 500):  # ค่อย ๆ เพิ่ม thrust 0→40000
    setpoint(thrust=t)
time.sleep(2)                       # ลอยนิ่ง

for _ in range(50):               # ร่อนหน้า-หลัง เบา ๆ
    setpoint(pitch=10, thrust=30000)
    setpoint(pitch=-10, thrust=30000)

for t in range(40000, -1, -500): # ค่อย ๆ ลด → ลงจอด
    setpoint(thrust=t)
setpoint()                              # disarm
cf.close_link()

6 กฎหมายโดรนในประเทศไทย (กสทช. & CAAT)

สรุปโดยย่อสำหรับการเรียน/ทดลอง — ก่อนบินจริงต้องตรวจสอบประกาศฉบับปัจจุบัน จากเว็บทางการ: CAAT · กสทช.

🏛️ CAAT

สำนักงานการบินพลเรือนแห่งประเทศไทย — ดูแล การขึ้นทะเบียนโดรน + ใบอนุญาตนักบินอากาศยานไร้คนขับ

📡 กสทช.

กำกับดูแล การใช้คลื่นความถี่วิทยุ (WiFi/RC ย่าน 2.4 GHz และ 5.8 GHz) — อุปกรณ์ที่ได้มาตรฐานใช้ได้โดยไม่ต้องขออนุญาตรายบุคคล

👮 ตำรวจ

บังคับใช้กฎหมายในพื้นที่ — ผู้ฝ่าฝืนอาจถูกดำเนินคดีตาม พ.ร.บ. การเดินอากาศ

ข้อควรรู้หลัก (โดยย่อ)

ประเด็นข้อกำหนดโดยย่อ
น้ำหนัก 250 กรัมขึ้นไป (รวมแบต)ต้อง ขึ้นทะเบียนกับ CAAT + ติดป้ายทะเบียน + ทำประกันภัยความรับผิดต่อบุคคลภายนอก
อายุผู้ขึ้นทะเบียนต้อง อายุ 20 ปีบริบูรณ์ — นักเรียนที่อายุน้อยกว่า ให้ใช้ชื่อครู/ผู้ปกครองเป็นผู้ขึ้นทะเบียน และบินภายใต้การดูแล
เขตห้ามบินรอบสนามบิน (รัศมี ~9 กม.), เขตพระราชฐาน/สถานที่ราชการทหาร, เรือนจำ, โรงพยาบาล, พื้นที่หวงห้ามอื่น ๆ
ความสูงห้ามบินสูงเกิน 90 เมตร จากพื้น
สายตา (VLOS)ต้อง มองเห็นโดรนได้ตลอดเวลา — ห้ามบินไกลจนมองไม่เห็นหรือบินแบบ FPV ล้วนโดยไม่มีคนมอง
กลางคืนห้ามบินหลังพระอาทิตย์ตก – ก่อนพระอาทิตย์ขึ้น เว้นแต่ได้รับอนุญาต
เหนือผู้คนห้ามบินเหนือฝูงชน / ตัวบุคคล / ยานพาหนะ โดยไม่ได้รับอนุญาต
ทิ้งสิ่งของห้ามทิ้งสิ่งของหรือของเหลวจากโดรน
บินเพื่อการพาณิชย์ต้องมีใบอนุญาตนักบินอากาศยานไร้คนขับ + ขออนุญาตจาก CAAT

ด้านคลื่นความถี่ (กสทช.)

  • โดรนของเราใช้ WiFi / RC ย่าน 2.4 GHz (และ 5.8 GHz) — อุปกรณ์ที่ได้รับรองมาตรฐานทั่วไปใช้ได้โดยไม่ต้องขอใบอนุญาตรายบุคคล
  • ห้ามดัดแปลงเพิ่มกำลังส่ง เกินกว่าที่ประกาศ กสทช. กำหนด (EIRP) — อย่าเพิ่มแอมป์/เสาอากาศแรง ๆ
  • ห้ามกวนหรือรบกวนสัญญาณวิทยุของผู้อื่น (รวมถึง WiFi บ้าน/สาธารณะ)

สำหรับโดรนของเรา (ESP32-S3 SuperMini DIY)

  • ชั่งน้ำหนักจริง (รวมโครง+มอเตอร์+ESC+แบต) — โครงการเรียนในร่มส่วนใหญ่ต่ำกว่า 250 กรัม แต่ถ้าเกินต้องขึ้นทะเบียนกับ CAAT
  • แนะนำบินใน ห้องปิด/พื้นที่ส่วนตัว ที่ปลอดภัย และใช้ใบพัดป้องกัน (prop guard)
  • ครูเป็นผู้ควบคุมดูแลการบินในห้องเรียน — อย่าบินนอกพื้นที่โดยไม่จำเป็น
  • อย่าบินใกล้ตัวบุคคล/สัตว์ หรือในที่ที่มีคนพลุกพล่าน
⚠️ ข้อควรระวังทางกฎหมาย — เนื้อหานี้เป็นสรุปโดยย่อเพื่อการศึกษา กฎหมายและประกาศมีการปรับปรุงอยู่เสมอ ก่อนบินจริงกรุณาตรวจสอบประกาศฉบับปัจจุบันจากเว็บไซต์ทางการของ CAAT และ กสทช. เสมอ

7.4 เทคนิคการสร้าง Loop (โค้ดและกระบวนการ)

🔄 Loop ส่งคำสั่งบิน

คำสั่งบินต้องส่งต่อเนื่องทุก ~20ms — ใช้ while True + time.sleep(0.02) พร้อมเงื่อนไขหยุด (ครบรอบ / Ctrl+C) กัน infinite loop

🔁 Loop อ่านเซนเซอร์

ใช้ LogConfig + data_received_cb — callback ถูกเรียกทุกครั้งที่มีข้อมูล (เช่นทุก 50ms) ไม่ต้องเขียน while เอง

⚙️ Control loop ใน firmware

ESP-FLY รันลูปควบคุม ~500 Hz (อ่านเซนเซอร์ → attitude → PID → mixer → PWM) ใน FreeRTOS task — ปกติไม่ต้องแก้ ยกเว้นจูน PID

♻️ Retry loop (เชื่อถือได้)

งาน flash/ตรวจซ้ำควรมี retry: ลอง N ครั้ง + รอระหว่างรอบ (เช่น for i in range(5) + time.sleep(1)) — กัน USB หลุดชั่วคราว

💡 เทคนิควนถาม AI (iterative prompting) — ถามทีละขั้น → ตรวจผลจริง (build/flash/รัน) → เอา error ใหม่ไปถามต่อ เหมือน debug วนรอบ จนกว่าจะผ่าน อย่าถามครั้งเดียวจบแล้วเชื่อทันที

  • มอเตอร์ M1–M4 ต่อ GPIO 4,5,6,7 ถูกตำแหน่ง (ทิศหมุน CW/CCW ตามแผนภาพ)
  • ใบพัด: ตำแหน่งถูก + เกลียวแน่น (ชุด CW/CCW คนละชุด)
  • แบตเตอรี่: ขั้วไม่สลับ · ต่อเป็นลำดับสุดท้าย
  • ถอดใบพัดตอนทดสอบซอฟต์แวร์ / ใส่ prop guard ตอนบิน
  • ตรวจ boot log: WHO_AM_I=0x38 → I2C [OK] → Ready to fly.
  • บินในพื้นที่ปลอดภัย + ตรวจกฎหมาย (หัวข้อ 6)
